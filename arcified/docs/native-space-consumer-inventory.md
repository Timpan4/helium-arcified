# Native Space consumer inventory

Recorded 2026-10-23. Status: source-backed, bounded inventory for the next gate in the [integration plan](native-space-integration.md#source-design-exit-and-consumer-inventory), [source references](native-space-source-references.md), and [design response](reviews/native-space-design-response.md). Production feasibility and exhaustive consumer coverage remain unproven.

The physical host cannot be separated by changing a Profile getter. Production creation, widget destruction, close state, collections, commands, sessions and UI anchoring all consume the combined Browser/window invariant. This inventory identifies concrete source edges, their proposed responsibilities and the first checkable change at each edge. The [feature catalog](research/native-space-consumers/feature-members.md) enumerates every pointer member in the fetched Chromium BrowserWindowFeatures header. It does not establish the enabled Helium feature set or close the implementation/caller audit.

## Authority and evidence identity

The owner-approved target is the same actual native OS window across Profiles, with immutable Profile-bound browsing contexts and exact live-page transfer between requesting hosts within the page's actual Profile. Keep TabModel, WebContents, controller and document identity. A hidden Browser, backing OS window, replacement window, clone, reopen or relabeled Profile does not satisfy it. The chosen design retains Profile-bound child chrome, without retaining an unmodified BrowserView as another widget delegate.

The [clean v3 review](reviews/lifecycle-review-round-3.md) accepts the standalone contract/model and synthetic routing scope. It supplies no native feasibility proof. The mapping is one Profile per Space, with shared Profiles allowed; sign-ins, site settings and Favorites belong to the actual Profile; themes belong to Spaces; approved saved outbound links produce temporary branches in the source page's current attachment and Profile. Safety signals, cleanup, destructive actions and populated cross-Profile migration/source disposition remain **OPEN**. This inventory does not choose those policies or authorize native implementation.

## Ownership vocabulary and common obligations

| Proposed responsibility | Meaning |
| --- | --- |
| Host, H | The one physical OS window, widget delegate/frame, native lifetime, process liveness and physical activation. It outlives presentation switches and empty contexts. |
| Context, C | The exact Profile, homogeneous tab container, Profile services, context-local session identity and retained context chrome state. This is not a new content::BrowserContext or a changing legacy BrowserWindowInterface. |
| Presentation, P | A revocable binding from the host to an attachment, context and page. It grants visible chrome, command, focus, accessibility, popup-anchor and theme authority. Context ownership alone does not imply presentation. |

For every edge below, the proposed owner is an extraction responsibility, not an existing supported API or a proposed facade. Initialize context services once under the actual Profile; attach presentation only after its dependencies are ready. Before detach or destruction, revoke input, invalidate originating bindings, retain ownership of unfinished pages/operations, and unregister observers in dependency order. Queued work must retain its originating context/page and validate liveness; it must not rediscover a different target from current selection. Preserve WebContents-before-Profile destruction. Session transitions and keepalive releases must follow actual context/host loss, never a Space switch. These obligations apply to the checks below; they are not implemented or runtime-tested.

## Production consumers

### E01. Production construction and keepalives

[Browser::Create, 233 to 245](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/browser.cc#233) transfers a new Browser to the exact Profile's manager. [Browser construction, 267 to 335](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/browser.cc#267) creates the Profile-bound tab strip, process BROWSER keepalive, regular-Profile keepalive, features, window and session record in one constructor. Custom-window injection is test-only. The callback production overload [posts completion after Browser creation, 140 to 164](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/browser_window/internal/create_browser_window_non_android.cc#140); it is not a windowless-context factory.

Proposed C/H split: extract production context initialization from physical host creation, with independent keepalive ownership and readiness publication. The first checkable change is to separate the window-construction call and its dependencies from the Profile/tab/service initialization sequence, without weakening creation-status checks or CHECK_IS_TEST. Failure before readiness must publish no usable binding or session record, and release reservations in reverse order. Prove ordinary-window behavior first, then host/context creation failure and empty-host liveness. A regular-Profile keepalive does not prove OTR or guest correctness.

### E02. BrowserView, BrowserWidget and destruction authority

[The production factory, 31 to 84](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/views/frame/browser_window_factory.cc#31) creates BrowserView and its BrowserWidget. [BrowserView, 1089 to 1094](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/views/frame/browser_view.h#1089) uniquely holds the widget and retains a const owner pointer expected to outlive the view. [Widget teardown, 116 to 142](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/views/frame/browser_widget.cc#116) closes owned widgets, invokes the owner's feature teardown and uses BrowserView as delegate. [Native destruction, 394 to 406](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/views/frame/browser_widget.cc#394) forcibly completes that Browser's close path and synchronously deletes it through its manager.

Proposed H owns the delegate, frame, owned native UI and destruction notification; C owns retained child chrome. First extract Browser-specific teardown/deletion authority from these widget callbacks into the production lifetime owner, preserving the legacy ordinary-window order until the host path exists. Do not reparent an unchanged BrowserView. Check native destruction during construction, synchronous observer reentry, owned modal-widget teardown, duplicate completion and the already-posted deletion in E04. Host loss must invalidate lookup/input before reconciliation and must not select a Profile to delete from the presented view.

### E03. Profile-keyed manager and OTR release

[Manager destruction/shutdown, 32 to 55](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/browser_manager_service.cc#32), [registration/deletion, 81 to 177](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/browser_manager_service.cc#81), and [subscription storage, 97 to 115](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/browser_manager_service.h#97) join owned Browsers, activation order, close notifications and Profile lifetime. Removal extracts an entry before reentrant destruction; subscriptions outlive the Browser. Primary OTR cleanup and app-exit notification are separate paths. [The factory, 14 to 44](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/browser_manager_service_factory.cc#14) uses exact BrowserContext selection and HistoryService dependency.

Proposed C remains exact-Profile keyed; H must have an independent lifetime owner. First separate context registrations and availability from physical-window creation/activation/close notifications. Preserve removal-before-destruction and callback lifetime. Check shutdown with inactive contexts, reentrant observers, last regular/OTR context, printing-preview contents and pending transfers. Do not normalize contexts to original Profile or copy regular keepalive behavior to OTR. [Keepalive acquisition/release, 31 to 102](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/profiles/keep_alive/scoped_profile_keep_alive.cc#31) includes acquisition failure and UI-sequence deferred removal; a raw Profile pointer is not equivalent.

### E04. Empty tab strips and the two deletion paths

[Browser::TabStripEmpty, 612 to 616](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/browser.cc#612) calls window Close. [UnloadController::TabStripEmpty, 576 to 580](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/unload_controller.cc#576) independently marks the Browser closing, blocking subsequent additions. [Close completion, 942 to 983](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/unload_controller.cc#942) marks deletion, notifies observers, checks last-browser shutdown and posts weak-pointer deletion. E02 also performs synchronous deletion on native-widget loss.

Proposed C reports empty state, while coordinated H close controls host destruction. First split both empty-strip effects from actual close approval and final deletion; changing Browser::TabStripEmpty alone is insufficient. Check a transferred last tab, empty selected attachment with sibling pages, empty context with other Profiles, fully empty host, canceled close, post-close insertion and widget loss before posted deletion runs. Switching or detaching must not close session records or release host liveness. Keep the existing no-add-after-delete-scheduled guard. The downstream last-tab flag adds a tab on close paths and is not an empty-host mechanism.

### E05. Downloads, application quit and session-end shutdown

[IsLastWindow, 69 to 93](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/unload_controller.cc#69) counts Browser interfaces, skipping closing entries. [Download close decisions, 810 to 938](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/unload_controller.cc#810) combine all-Profile downloads, exact-Profile last-window state, OTR/guest teardown and a native confirmation dialog. macOS/ChromeOS regular downloads have a separate branch. [BrowserCloseManager, 191 to 243](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/lifetime/browser_close_manager.cc#191) shuts down session services before iterating close, and has a session-end path closing tabs and synchronously destroying Browsers. [Application lifetime, 300 to 347](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/lifetime/application_lifetime_desktop.cc#300) consumes BROWSER keepalive state.

Proposed H counts physical hosts; C accounts for affected Profile services/pages; app quit coordinates all of them. First replace the count inputs and close-iteration meaning, retaining existing download/unload vetoes rather than inheriting destruction from a selected context. Check a Profile with contexts in multiple hosts, multiple Profiles in one host, pending download response after a switch, quit cancellation, background liveness and session-end ordering. Existing force-skip paths are source facts, not newly approved destructive policies. Full application/background/printing shutdown closure remains open.

### E06. BrowserWindowFeatures lifecycle and enabled-feature surface

[Global collection, 29 to 125](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/browser_window/internal/global_browser_collection.cc#29) stores creation/activation order, publishes Browser events, derives active state through GetWindow, and counts private/guest Browsers.
