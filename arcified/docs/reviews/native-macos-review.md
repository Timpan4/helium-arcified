## New finding

### 1. [P2] Check filesystem identity when excluding input repositories from work paths

Location: `arcified/native/tooling/macos.py:167`, with CLI normalization at `:222`.

The overlap guard compares POSIX path spellings with equality and `is_relative_to()`. On macOS these comparisons are case-sensitive even when the underlying APFS volume is case-insensitive. Calling `resolve()` first removes symbolic links but does not canonicalize the case of ordinary absolute path components. With a fork at `/Users/owner/helium-arcified`, a nonexistent work directory `/Users/owner/HELIUM-ARCIFIED/new-work` therefore passes the guard while referring to a directory inside the fork on case-insensitive APFS. The same problem applies to the platform checkout. Following the accepted plan would create its cache, resources and prepared source under an input repository, violating the documented isolation contract.

Apple documents [case-insensitive APFS as the macOS default](https://developer.apple.com/library/archive/documentation/FileManagement/Conceptual/APFS_Guide/FAQ/FAQ.html). Python documents [`is_relative_to()` as a string-based operation](https://docs.python.org/3.13/library/pathlib.html#pathlib.PurePath.is_relative_to). The [CPython 3.13 POSIX resolver](https://github.com/python/cpython/blob/v3.13.0/Lib/posixpath.py#L393) preserves ordinary component spelling after `lstat`, consistent with the platform guide's Python version. This finding requires neither a symlink nor a change to `input_identity.py`.

A focused Linux reproduction reused the existing synthetic macOS fixture, mapped `os.stat` and `os.lstat` calls for the alternate-case `FORK` component to the actual `fork` component, and called the real `Path.resolve()` and `macos.prepare()`. The resolved spelling remained alternate-case, `work.parent.samefile(fork)` returned true, and preparation returned `PLANNED`. The work directory remained absent. This proves the guard's behavior under emulated case-insensitive lookup; it is not an execution test on macOS or APFS. The existing overlap test covers identical spellings only.

Reject overlap using filesystem identity for existing ancestors, including the nearest existing ancestor of a new work path, rather than relying only on lexical containment. Preserve correct behavior on both APFS variants; blindly lowercasing all paths would reject distinct directories on a case-sensitive volume. Add a regression that accepts separate work and rejects alternate-case aliases into either input repository, with native APFS verification when available. Preserve the public API signatures.
