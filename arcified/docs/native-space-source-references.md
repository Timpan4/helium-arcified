## C1. Desktop window and Profile ownership

- [browser_window_interface.h, lines 77 to 99](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/browser_window/public/browser_window_interface.h#77) distinguishes native window access, immutable semantic Profile ownership, same-Profile desktop tabs and session-unique window IDs. Its mobile exception does not establish desktop support.
- [browser.h, lines 266 to 283](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/browser.h#266) stores a const Profile pointer, Profile keepalive, unique window and unique tab strip. Session IDs are not guaranteed unique across sessions. Lines 99 to 106 identify Browser as a desktop window owned by BrowserManagerService.
- [browser.cc, lines 267 to 326](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/browser.cc#267) constructs the tab strip with that Profile, obtains its keepalive, creates its window and registers with the appropriate session service. Lines 309 to 310 enforce test-only custom windows.
- [create_browser_window.h, lines 145 to 147 and 208 to 245](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/browser_window/public/create_browser_window.h#145) documents the custom test window and initialization contract. A returned interface need not have a fully initialized OS window; the asynchronous creation callback provides that guarantee. Profile, session ID and type remain fixed.

## C3. Live identity and handoff

- [tab_model.cc, lines 52 to 116](https://chromium.googlesource.com/chromium/src/+/a49e2e3d4addfd84e765b52afe230bedb81096db/chrome/browser/ui/tabs/tab_model.cc#52) owns WebContents and TabFeatures.
