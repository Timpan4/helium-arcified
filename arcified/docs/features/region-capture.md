## Geometry and local behavior

`RasterMapping` describes an axis-aligned native overlay DIP rectangle mapped onto an exact source raster, plus its visible/selectable rectangle. The host supplies both raster dimensions. Different horizontal and vertical ratios are supported. Native-view DIPs are distinct from CSS coordinates, screen coordinates and raster pixels. The picker never assumes that CSS equals DIP or multiplies by a guessed device scale.

`SelectRegion` normalizes corner order, clamps both corners to visible content and proposes half-open integer pixel edges. Left/top round up; right/bottom round down. Floating-point cancellation can place that proposal outside the selection, so rounding alone never authorizes a crop. Each proposed pixel edge is independently enclosed in DIP space using the exact affine relation `start + (end - start) * edge / pixels` over the supplied binary floating-point values. The crop is returned only when those enclosures and the rounded `displayed_boundary` all lie inside the clamped selection. Because the transform is increasing, this also contains every included pixel's entire true extent within both the selection and visible bounds. The host must draw `displayed_boundary` during dragging and selection. A nonrectangular occlusion cannot be represented by this mapping. The host must deny capture until it can establish an exact visible rectangle rather than approximate one that includes hidden content.

The enclosure calculation uses `double` throughout. It does not rely on `long double` being wider. Each inexact arithmetic operation expands outward by `std::nextafter`; this is a representable-neighbor bound, not an epsilon or tolerance. TwoSum detects exact sums. Fused multiply-add detects exact products and quotients only when the operands' binary exponents prove that the residual cannot underflow. Otherwise the enclosure expands even if the computed residual is zero. Exact raster endpoints bypass arithmetic. Multiplication before division preserves common exact interior boundaries, such as `-100 + 200 * 50 / 500 == -80`; division first avoids multiplication overflow when needed. Uncertain containment returns `kEmptySelection`, even if a smaller valid crop might exist. The component neither promises a maximal crop nor searches for one after refusing a candidate.

These guarantees require IEC 60559 binary floating point, round-to-nearest arithmetic, gradual underflow, correctly rounded operations including `std::fma`, and compilation without fast-math or reassociation. Compile-time checks require binary IEC 60559 `double`, exact representation of `int` in `double` and `FLT_EVAL_METHOD == 0`, so intermediate arithmetic has the declared type's precision. A non-nearest rounding mode returns `kInvalidGeometry`. Hosts must retain gradual underflow, including disabling flush-to-zero and denormals-are-zero modes. This floating-point contract still needs confirmation in each native build. A rounded displayed edge need not equal the mathematical rational edge, but both must independently satisfy containment.

Nonfinite coordinates, nonpositive/overflowing extents, invalid raster dimensions and a visible rectangle outside the raster are rejected. Empty and subpixel regions produce `kEmptySelection`; they never produce an empty native source rectangle. The integer maximum follows the `int` representation used for pixel edges, not a product quota. There is no duration, image-size quota, timer or retry policy in this component.

The picker represents Ready, Dragging, Selected, Cancelled and Submitted as separate states. A pointer gesture must start inside the intended visible pane. Drag motion may leave the pane, but clipping retains the same target. Release selects without submitting. Keyboard UI uses `SelectCorners` through the same geometry path. An empty replacement removes the prior selection. Invalid numeric input reports an error without applying the edit.

`Confirm` requires a separate explicit action and a fresh host snapshot. It returns one owned `RegionSelection` and ends the picker. Repeated confirmation cannot emit another selection. Pickers cannot be copied; moving one also ends the source instance. Escape, pointer cancellation/lost capture and native dismissal can cancel Ready, Dragging or Selected. Cancellation removes geometry, preserves its original reason and prevents later confirmation. After submission, capture owns cancellation of pending acquisition, preview and saving.

## Host policy and capture seam

The parent accepted this local interface before integration. Types remain independent of capture headers.

1. Resolve the intended native page/pane through the existing authoritative host association. Supply `PageId`, immutable `ProfileId`, `Attachment`, optional `SplitId`, nonempty committed-document token and visual revision. The references do not authorize access or verify native liveness. A split reference plus page identifies the intended pane without inventing another pane identity or using a mutable tab index.
2. Produce the exact visible-pane raster dimensions and its native DIP transform. Advance the visual revision on scroll, layout, zoom, surface or WebContents replacement, even when dimensions stay the same. Do not reuse a document/revision token to conceal an intervening change. Coordinate conversion from CSS belongs to the host/capture plan, outside this picker.
3. Obtain an authoritative decision for screenshot restrictions and sensitive content. `Permission` defaults to Unknown. Unknown, Denied and SensitiveContent all refuse picker creation or terminate an active picker on revalidation. Explicit Allowed is required. This is a conservative refusal boundary, not a new sensitive-content classifier or permission override. Include the intended Profile's restrictions, private-content rules and native capture restrictions; do not infer approval from a URL or foreground appearance.
4. Route native events to the picker on the host's serialized sequence. Draw `displayed_boundary`, provide accessible keyboard corner selection and an explicit confirmation action, and route Escape/pointer cancellation/dismissal. Use `Revalidate` on target and policy notifications and supply a fresh authoritative snapshot to `Confirm`. Any changed page, Profile, attachment, split, document, visual revision, mapping or raster dimensions cancels the selection. Returning to the original target does not revive it.
5. Copy the submitted selection into capture's local optional `VisibleRegion {Target target; PixelSize raster_size; PixelRect crop}` using visible-pane scope only. Copy its original target verbatim, including page, Profile, attachment, optional split, `committed_document` into capture's `document`, and `visual_revision`. Do not rebuild that target from fresh host facts. Capture compares the original selection target with current facts before acquisition so a stale picker cannot acquire a newer document or surface. Copy the exact raster dimensions and convert the half-open crop edges to capture's `{x, y, width, height}` as `{left, top, right - left, bottom - top}`. The host must establish that the DIP mapping and capture's CSS-to-raster plan describe the same exact raster. Never reinterpret these integer crop edges as DIPs or CSS coordinates, and never combine a region with full-page scope.
6. Capture owns acquisition, full incoming RGBA raster validation, bounded crop copying, preview/export and subsequent cancellation. Revalidate the same identity, document, visual revision, current geometry and policy again when asynchronous capture completes, before exposing or exporting pixels. The picker submission is a snapshot, not a native reservation or permission token. Discard stale/denied results. Capture must refuse a raster-size mismatch. Library insertion and downloads integration need their own success/failure handling; this component performs neither.

An incorrect or echoed host snapshot cannot be detected by this local model. Real native event provenance, restrictions, surface selection, overlay exclusion and asynchronous revalidation are required before claiming correct capture. Capture failure leaves lifecycle ownership unchanged because this component never mutates it.

Both executables printed `region-capture geometry and picker fixtures passed`; the sanitizer run emitted no diagnostics. A further strict build and run with `-mlong-double-64` also passed, exercising the same regressions with Clang's 64-bit `long double` mode. That compiler-mode check is local Linux evidence, not a Windows or macOS build. The formatter check emitted no diagnostics. Compiler warnings are errors. No separate C++ linter or Markdown formatter is declared for this slice. Per-file `git diff --no-index --check /dev/null <path>` checks emitted no whitespace diagnostics for all four new files. Their exit status 1 records new-file differences.

The fixtures cover fractional and unequal axis scaling, negative origins, reversed corners, clipping, an indivisible pixel, empty/subpixel refusal, NaN/infinity and representational extremes. Boundary regressions cover offsets lost when subtracting a negative raster origin, all four inward edges, the true `1/3` pixel edge beyond its rounded-down display value, preservation of exact boundaries and rejection of non-nearest rounding. Because production arithmetic uses only `double`, those numerical regressions do not gain hidden precision from Linux's wider `long double`; they do not replace Windows or macOS compiler/runtime acceptance. The fixtures also drive pointer selection, keyboard corner replacement, explicit single submission, every pre-submission cancellation phase, moved-from refusal, permission refusal and each target/mapping field changing. They use synthetic IDs/tokens and numeric geometry only. They prove local behavior, not native UI, actual pixels, screenshot policy enforcement or cross-platform compiler/runtime behavior. A composed region-to-capture fixture belongs to capture's path and is reported separately by its primary.
