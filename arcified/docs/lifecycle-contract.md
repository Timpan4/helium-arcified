# Ownership and lifecycle contract

Semantic contract version: **3**. Recorded: 2026-10-23. Scope: [issue 24](https://github.com/Timpan4/helium-arcified/issues/24).

This document and the [standalone C++ model](../native/model/lifecycle.h) define a local ownership core and executable synthetic transitions. They do not implement native browser tabs. The existing [extension state](../extension/src/state.ts) stores URL snapshots and remains unchanged. Linux, Windows and macOS native integration and runtime behavior remain unverified. Issue 24 still needs the owner decisions and native evidence identified below.

Version 3 names the semantic contract, not an on-disk schema. Version 2 added saved-page transfer and logical Space selection within a window; those approved behaviors and the borrowed-command-ID fix remain intact. Version 3 adopts the Profile/Space and settings scopes above and adds the pure `PlanSavedPageLink` API for the newly approved outbound-link policy. It does not change prior transition signatures. Fixtures name version 3, and `CheckContractVersion` rejects all other versions, including version 2. The independently reviewed native design was based on version 2. Its eventual adapter must explicitly adopt version 3 and the routing/classification/actuation boundary; this change does not update or claim review of that design. No disk parser, migration or crash recovery is implemented. Future serialization must validate the complete reference graph and version. Ownership-semantic changes require a new contract version and updated fixtures; editorial clarifications do not imply a migration.

## Identities and ownership

IDs are opaque and strongly typed. Their text carries no URL, credentials, Profile inference or display-name meaning. The caller allocates IDs that are never reused and serializes commands and native event reports. The model rejects empty IDs and duplicate currently registered IDs; it has no allocator, tombstone store or stale-event reconciliation. Display names and imported labels are not identities. Distinct explicit items may save the same URL; URL/title matching never merges their identities or crosses a Profile boundary.

| Entity | Identity and owner | State and references |
| --- | --- | --- |
| Profile | `ProfileId`, local root | Security/storage boundary. The model stores identity only, never cookies, account data or actual settings. Sign-ins, site settings and Favorites use this ID, not the window. |
| Space | `SpaceId`, exactly one owner-chosen `ProfileId` | Durable organizational identity. It can exist without windows. It owns Space-kept items and the approved Space theme scope. Multiple Spaces may share a Profile. No theme payload is modeled. |
| Persistent item | `ItemId`, owned by either `SpaceId` or `ProfileId` | Saved destination. A Space-owned item is "Kept in this Space". A Profile-owned item is a standalone "Profile shortcut", visible from Spaces in that Profile. |
| Shortcut alias | `ShortcutId`, owned by `ProfileId`, references `ItemId` | Adds a Profile shortcut for an existing kept item without creating another persistent destination or page. Alias and target must use the same Profile. Removing the alias leaves the target and its live page intact. |
| Live page | `PageId`, immutable `ProfileId`, one `PageOwner` variant | The sole owner of `current_navigation`. Either a temporary tab or a saved item supplies its ownership association, never both. Each live page has one window attachment. |
| Window | `WindowId`, optional selected `SpaceId` | Contains logical Space attachments and local live pages. It owns neither the Space nor its saved destinations. Selection may switch between attached Spaces with different Profiles without changing `WindowId` or any page's Profile. The approved native behavior still needs a secure implementation. |
| Window attachment | Unique `(WindowId, SpaceId)` pair | Connects a window to existing Space state. It contains no cloned item list or navigation. Detach requires no live pages or layouts to reference it. |
| Temporary tab | `TemporaryTabId`, stored in its live page's owner variant | Records its original attachment. It has no saved destination. The model has no temporary-tab transfer operation. Keep replaces this association while retaining `PageId`, Profile, attachment and activity. |
| Split layout | `SplitId`, owned by an attachment | Ordered, distinct `PageId` references in the same attachment. No URL, history, credentials or renderer state. Removing a layout leaves pages intact. Closing or transferring a page removes its old references; empty layouts disappear. A remaining single reference is retained without deciding native presentation. |

Every mutating command takes owned ID, attachment and payload values before touching model storage. Public getters remain const views whose references can be invalidated by later mutations. Passing an ID or attachment directly from a getter into a command is supported. Private page-erasure and reference-pruning helpers also own their command IDs, so vector compaction or layout/page erasure cannot change the requested target midway through a transition.

Profile shortcuts have two representations with explicit consequences. A standalone shortcut owns a saved destination. An alias exposes an existing item's destination and live page. Removing an aliased target is blocked until its aliases are resolved. Detaching an alias into an independent destination is a future explicit action, not an implicit delete side effect.

Folder membership and sidebar/top-strip presentation are organization and view state. Neither changes ownership or lifecycle. Imported Arc "Today", "Pinned" and "Favorite" labels may be retained as provenance aliases for Temporary, Kept in this Space and Profile shortcut. Imported spelling must not create a fourth lifecycle or duplicate a page. Import and folder implementation are outside this model.

## Navigation and transitions

`saved_destination` and `current_navigation` are separate values. Ordinary observed navigation, whether on the same site or another site, updates only the live page. The saved destination changes only through a future explicit edit operation; none is implemented here. Keep captures the current destination once. Reopening a closed item uses its saved destination, not its last live location.

The model accepts already validated, nonempty destination strings. It does not parse sites, classify origins, execute requests or bypass browser URL policy. The embedding browser must validate URLs and enforce its security checks. `RecordNavigation` reports an observed commit; it is not permission to navigate. Synthetic `OpenItem`, `Reset` and close operations demonstrate semantic outcomes only. A native integration must coordinate actual browser success/cancellation before committing the corresponding state and must not claim success based on this in-memory result alone.

`PlanSavedPageLink` is a const decision over a saved live page, explicit `NavigationKind`, caller-supplied `SiteRelation` and validated target destination. `SiteRelation` describes the target relative to the source's current committed document, not its saved destination. The embedding browser owns authoritative site classification and navigation-kind provenance. No URL-prefix, domain, origin or string comparison supplies classification here. The eventual GURL/native classifier and its redirect handling are separate implementation work.

Only `kLink` plus `kOutbound` yields a `TemporaryBranchPlan`, an owned snapshot of source `PageId`, immutable `ProfileId`, current attachment and target. Planning allocates no IDs, changes no model state and does not navigate, reset, close, transfer or change activity on the original. Unknown classification and same-site links return distinct refusals; same-site routing remains open. Redirects, scripts, typed navigation and other triggers return outside-approved-scope even with an outbound classification. These refusals withhold this planner's authorization; they do not mandate a browser-wide navigation block or approve an in-place fallback.

The native caller must validate browser URL/security policy, revalidate source identity, current document, Profile, attachment and classification before actuation, and coordinate actual native success/cancellation before recording any state. A plan is neither a reservation nor a commit token; source transfer or navigation can make it stale. Cancelled/failed native creation records nothing. After successful temporary creation under the same Profile and attachment, the caller reports it through existing `OpenTemporary` with fresh, non-reused page/tab IDs and the actual committed destination. It must coordinate model preconditions before actuation and reconcile native success if state changes or reporting fails. A redirect is not a new approved link and must not reuse the link plan as routing authorization. The planner and synthetic report fixture provide no native transaction, redirect policy or stale-event protocol.

| Action | Supported outcome | Refusal or unresolved boundary |
| --- | --- | --- |
| Attach another window to a Space | Same saved item IDs/destinations, no copied temporary tabs | Missing window/Space is rejected. No browser or account is created. |
| Select an attached Space | `SelectSpace` updates only that window's selected Space, including across Profiles | Missing window/Space or unattached destination is rejected. No page is reprofiled, moved or recreated. Selection and page transfer are separate commands; this logical state is not native focus evidence. Detaching an empty selected attachment clears the selection. |
| Open a saved item | Creates a page in its owning Space, or in a same-Profile Space for a standalone Profile shortcut | Requires the destination attachment. A Profile mismatch is rejected. |
| Select an already-live saved item, including from another window | `OpenItem`/`OpenShortcut` transfer its existing page to the requesting window and return `OpenedPage` with `kExisting` and the same `PageId` | Preserve navigation, activity, item ownership and immutable Profile. No allocation, reload or renderer/history clone. The unused candidate page ID is not registered. The destination attachment must exist for live and closed targets alike. Native focus and transfer success remain unverified. |
| Transfer a saved live page explicitly | `TransferSavedPage` changes only its attachment and prunes all old split references within one synchronous transition | Only saved pages qualify. A Space-kept item stays in its owning Space; a standalone Profile shortcut may use any attached Space in the same Profile. Unknown/protected activity is retained rather than reset or closed. Same-attachment transfer is a no-op, including layouts. Missing destinations, Profile mismatch, wrong owning Space and temporary-page transfer are refused before mutation. No layouts follow the page and no target layout is invented. |
| Open an alias from another Space in the same Profile | Resolves its target in the owning Space of the requesting window, transferring an existing page if necessary | The owning Space must already be attached to the requesting window. It never silently converts a Space item into a page in the requesting Space. The adapter may offer an explicit attach/switch action. |
| Open a temporary destination | Creates a window-local temporary identity and live page | Duplicate IDs and missing attachments are rejected. No cleanup timer is started. |
| Keep a temporary page | Creates a Space-owned item from current navigation; preserves live page identity and protected work | Existing item ID or non-temporary page is rejected without changing ownership. |
| Plan an outbound link from a saved live page | `PlanSavedPageLink` returns a same-Profile, same-attachment temporary-branch snapshot without changing state, including for unknown/protected activity | Only authoritative browser-classified outbound links qualify. Missing/non-saved source, empty destination, unknown classification, same-site links and non-link triggers return explicit refusals. Native success must precede a separate `OpenTemporary` report. |
| Record navigation | Updates current navigation and invalidates the prior activity report | No saved destination or ownership change. It reports an actual commit, not routing approval. An outbound branch commit belongs to the new temporary page, not the retained saved source. |
| Reset a kept/shortcut page | Returns current navigation to the item's saved destination in the synthetic model | Requires reported quiescence. Temporary pages have no saved destination to reset. |
| Close a live page | Removes live state and its split references; saved item and aliases survive | Unknown/protected activity is refused. This does not remove a saved reference or implement Archive. |
| Close a window | Preflights all its live pages, then removes their runtime state, layouts and attachments together | Any unknown/protected page leaves the entire window state unchanged. Other windows' temporary pages and all saved entries survive. |
| Define/update/remove a split | Reorders/replaces page references or removes the layout without changing navigation | Missing, duplicate or differently attached pages are rejected before mutation. Pane count, geometry and focus policy are not defined. A residual single reference is model membership, not a UI split policy. |
| Move a closed saved item within its Profile | Changes organizational owner and preserves saved destination and aliases | A live item is refused. Different-Profile owners always return `kReopenRequired`, even when closed. |
| Explicitly copy a saved destination to another Profile | New item ID and, on explicit open, new page ID under the destination Profile; source remains | Copies only saved destination, never current navigation, history, cookies, authentication, protected work or aliases. This is a copy, not a completed move or Space reassignment. |
| Remove a shortcut alias | Removes that reference only | Target and page remain. |
| Remove a persistent item | Removes a closed, unaliased saved destination | Live or alias references block removal. Closing and deleting are distinct verbs. |
| Reassign a Space's Profile | Only an empty, unattached Space can change Profile | Populated or attached reassignment is refused. No live page is relabeled. |
| Remove Space/Profile | Only after all owned/referencing data is explicitly resolved | No implicit cascade, orphaned references, credential deletion or data-directory deletion. |

Archive, automatic cleanup, reset confirmation, grouped undo, session restoration, sleeping/discarded state, Peek and transient-window promotion are not implemented. A future Peek must reference its parent and existing live page identity, or explicitly create a separate page with its own Profile and lifetime. Promotion must change references/attachment through an approved transition, not clone navigation. No account, AI access, retention period, timeout, quota, capacity or cleanup schedule is inferred.

## Decisions still required

The owner explicitly left activity/cleanup/destructive-action and populated cross-Profile migration policy open. Keep those choices open; the conservative safety subset does not approve detection signals, cleanup, destructive confirmation or source removal. Version 2's saved-page handoff and same-window Profile switching, and version 3's mapping/settings scopes and outbound-link routing, are approved and are not reopened by missing native evidence. Other choices below remain unapproved.

| Choice | Concrete recommendation | Tradeoff and current model boundary |
| --- | --- | --- |
| Additional live instances of a saved item | If adopted later, make "Open another instance" a separate, explicit action with its own live identity. | The current model has one live page per saved item. The approved selection behavior transfers that page. It does not authorize duplicate live instances or cloned renderer/history state. |
| Same-site and other navigation routing | Choose same-site link behavior and policies for redirects, scripts, typed navigation and other triggers separately. | Only outbound links from saved pages are approved to branch. The planner refuses unknown/same-site/non-link cases without choosing an in-place fallback. Native browser classification is required; no domain parser is implied. |
| Active-work protection | Refuse automatic cleanup and Reset while activity is unknown, unsaved form work exists, capture/calls are active, or the user protects a page. Preserve applicable native before-unload and discard checks. Manual destructive actions need a consequence-specific review path. | Detection may be incomplete and can delay cleanup. The model has only Unknown, Quiescent and Protected reports. It refuses close/reset unless Quiescent, has no override, and does not certify an actual page safe. The exact signals, audio/download rules and manual-close review remain undecided. |
| Populated Space reassignment and cross-Profile move | Stage an explicit saved-destination reopen plan under the destination Profile; retain source pages/items until target success and explicit source disposition. Offer Cancel and Deny. | A new sign-in may be required, and renderer state cannot be promised recoverable. The model supports URL-only copy/open and safe denial, not a migration transaction or automatic source removal. |
| Closing shared live state and undo | Label the action Close live page, explain the owning window, and keep the saved item. Use a separate operation journal for reversible workspace mutations. | Shared metadata must not imply recoverable live forms or server effects. Per-window focus, remote close permission, last-window restoration and journal retention need their own decisions. The model implements no archive, history or undo promise. |
| Split/transient view behavior | Keep layouts as references. Dissolve a single-pane split visually; scope focus and commands to the selected page. Keep Peek associated with its parent until explicit promotion. | Native support and focus evidence are still required. The model tests reference validity and cleanup only; no implicit pane limit or Peek policy is adopted. |

## Native integration boundary

Adjacent Helium source patches were read, not executed. [Tab cycling](../../patches/helium/core/tab-cycling-mru.patch) already changes `TabStripModel` selection. [Lazy session restore](../../patches/helium/core/lazy-session-restore.patch) already handles restored tabs and split reconstruction. Its current restore path mentions pair-based native splits, which is an adapter constraint to investigate, not a capacity copied into this model. [Hibernate](../../patches/helium/core/hibernate-tab-context-menu.patch) consults native discard eligibility. [Context noise](../../patches/helium/core/noise/core.patch) associates state with `BrowserContext`. These are reuse points; no second native restore, discard or context system is introduced.

Build preparation belongs to a separate worker. This change adds no GN/CMake target, Chromium facade, quilt patch, tooling dependency or extension-state adapter. A future integration must bind `ProfileId` to the real Profile/BrowserContext, `PageId` to the authoritative native tab/WebContents identity, and attachment/layout references to native windows. It must reconcile native IDs and events without creating another navigation controller. It must preserve native security, before-unload, discard eligibility and actual restore semantics, and handle native cancellation/failure before reporting a semantic transition committed. In particular, the approved same-native-window Space switch must preserve isolated Profile storage, cookies and authentication contexts. The approved saved-page transfer must preserve the existing live page and renderer/history state rather than serialize, clone or reopen it. Logical selection/attachment updates do not prove that either native path is supported or safe.

Persistence, ID allocation/non-reuse, URL validation, native activity detection, asynchronous event ordering, migration transactions, journal recovery, native focus and presentation remain outside this in-memory model. No Linux/Windows/macOS native UI interaction, authenticated-page boundary, migration, restart durability, accessibility or performance claim is made. Closing issue 24 requires the remaining owner choices and scenario evidence from each target platform; passing these standalone fixtures alone is insufficient.
