# YAB inspiration for Arcified

Research date: 2026-10-23

Target: Timpan4/helium-arcified

Scope: official YAB product pages, manual, changelog, developers page, privacy page, and Arc/browser migration manual. No YAB installation, runtime inspection, account connection, or setup instructions were used. This report adds reference ideas to the Arc/Dia backlog; it is not evidence that the described behavior works in a shipped build.

## Evidence and platform boundary

YAB’s manual and changelog describe product behavior, while its landing and developers pages also make vendor performance and capability claims. None of these pages supplies independent runtime evidence or reproducible performance measurements. Use them as interaction references only. YAB is published for macOS 15.4 or later and runs on WebKit. Apple keychain access, system calendars, Live Text/OCR, WebKit inspector details, Touch ID, and the WebKit memory footprint are platform or engine-specific. Linux and Windows support must be established on Arcified’s own Chromium builds.

The site is internally stale: the home page reports version 0.32.2 while the changelog lists Yab 0.35 on October 22, 2026. The home page’s “40 MB” versus “1.4 GB” Chrome comparison has no workload, method, or machine disclosure. Neither version label nor memory comparison should become an Arcified target. Changelog entries are vendor-reported changes, not measured outcomes.

## Ideas mapped to the backlog

| YAB idea | Existing key or proposed slice | Recommendation and acceptance criteria |
| --- | --- | --- |
| Toggle the same tabs between a vertical sidebar and horizontal top row, preserve tab state, choose sidebar side, resize/hide it, and offer comfortable/compact density. | `sidebar-layout`, `tab-status`, `accessibility`, `window-chrome`; existing `split-horizontal` and `split-vertical` for pane orientation | Keep the existing slice. Add a layout choice to its acceptance criteria: switch sidebar/top tabs without changing tab identity, order, selection, or navigation; persist layout; make controls keyboard and accessibility-operable; test narrow/wide windows and each OS’s native caption area. Treat top tabs as an alternative presentation of the same state, not a second tab model. |
| One contextual field ranks actions from current state: selected text exposes text commands, current URL exposes page actions, typed questions promote Ask, and action menus explain what Return will do. | `command-bar`, `command-ranking`, `context-selector`, `site-search` | Refine these existing issues. Acceptance: context-sensitive ranking is deterministic and visible; selected text and current-page context are labeled; Enter’s action is explicit; Escape restores the prior focus/selection; no page text is sent merely by opening or typing in the field. Keep remote/AI actions behind `context-selector` and provider consent. |
| Import preserves Arc’s spaces, colors, pins, nested folders and paired splits; profile migration has a one-shot path plus item-by-item settings import, progress, and additive re-import. | `arc-import`, `browser-import`, `profiles`, `export` | Extend acceptance on the existing import issues: preview available data and omissions, let users include open tabs or choose categories, keep the source browser unchanged, make re-import idempotent, preserve profile separation, and clearly state where OS credential prompts or unsupported data limit migration. YAB’s direct files/keychain mechanisms are macOS-only and are not portable implementation requirements. |
| Developer mode attaches diagnostics to local servers: port and full URL in the tab, opt-in per server, error/request counts, copyable redacted diagnostics, rulers/live CSS, and a docked inspector that makes room for the page. | `developer-mode`; `boost-code` only for persistent site customization | Strengthen `developer-mode` with small acceptance additions: user grants local-server access; port labels distinguish same-host tabs; diagnostics target the right tab; copied logs redact credentials/cookies/tokens; closing tools stops their updates; docking does not obscure page content. Propose separate small slice only if implementation review confirms the ruler/live-CSS editor is absent: “Inspect and edit local page layout with reversible rulers.” Require preview, undo/reset, origin scoping, and explicit export of edits. Do not require WebKit inspector or YAB MCP compatibility. |
| Snippets can be imported from existing tools and inserted into writing flows. | No direct snippet issue; `command-bar` can provide discovery/invocation | Proposed small slice: “Save and insert user-authored text snippets.” Acceptance: create/edit/delete locally; choose a clear trigger or field action; preview expansion before insertion where a trigger could replace text; preserve cursor/undo; never upload snippet contents by default. Treat Raycast/Alfred import as a later adapter with format preview and duplicate handling, not part of the core ticket. |
| Local OCR/Live Text selects text inside an image. | `capture`, `page-reading`, `find` | Proposed small slice: “Select and copy text from an image using an available OS OCR service.” Acceptance: explicitly invoke on a selected image or capture, show detected text before copy/use, report unsupported image/origin states, and keep it separate from cloud AI context. Use platform adapters and verify Linux, Windows, and macOS independently. Apple Live Text is a macOS inspiration, not a Chromium or cross-platform mechanism. |
| A call follows the user across tabs in a small window, exposes mute/camera/leave controls, protects the call tab from sleep/tidy/close surprises, and offers the next meeting. | `pip`, `media-controls`, `tab-status`, `temporary-tabs`; no clear existing calendar-join slice | Improve existing media/call state criteria: calls remain visible and protected from automatic discard while active; closing asks before leaving; global mute targets the active call; test tab changes and multiple windows. Proposed separate slice for “Show and join an upcoming meeting from browser chrome” only after calendar source, permissions, and supported providers are decided. YAB’s macOS calendar aggregation and meeting shortcut depend on system APIs and must not be assumed portable. |
| Agent tasks browse in agent-owned tabs, stay out of the user’s history and focus, display task state, and allow the user to take over and hand back. High-impact send/pay/delete actions wait for explicit approval. | `context-selector`, `page-reading`, `streaming`, `citations`, `remote-provider`; new slice only after provider choice | Defer as an optional capability, not baseline Arc UX. Proposed small slices if the owner later chooses an agent: (1) “Run an agent task in a visibly separate browser workspace,” with profile/cookie boundary, history/visibility policy, task state, and cleanup/recovery; (2) “Pause and resume an agent task under human control,” preserving page/task context and showing what changed; (3) “Require approval for external side effects,” with a review card naming target, action, and data before send/pay/delete/upload. No task may share a user profile silently or treat web content as instructions. Do not adopt YAB’s agent limit, close timer, setup command, or MCP protocol as requirements. |
| Privacy is explained by data category and destination; local storage is distinguished from optional sync and third-party model processing. | `local-assistant`, `context-selector`, `remote-provider`, `page-reading`, `citations`, `export` | Reuse the existing privacy boundaries. Acceptance: show exactly which page/context leaves the device and which provider receives it; distinguish local storage, telemetry, crash reports, updates, sync, and model requests; disclose opt-in/out and deletion behavior; keep credentials out of prompts/logs; make sync opt-in and identify its encryption/data scope. YAB states that browser data is local by default, but also describes update checks, optional daily activity and crash reporting, optional end-to-end encrypted sync, and page data sent to Anthropic/OpenAI when agents are used. Do not reduce that to “nothing leaves the device.” |

## Distinctive interaction details worth preserving

- YAB’s field combines navigation, tab/history lookup, commands, site search, selected-text actions, and contextual suggestions, while exposing the chosen action and its shortcut. This strengthens the existing command-bar slices without requiring AI.
- The sidebar’s collapse/reveal behavior, edge resize, left/right placement, top-row alternative, and density setting form a coherent layout contract. The tab collection stays the same across presentations.
- Import communicates what will move, handles several browsers and profiles, supports category-level later imports, and makes a second import additive. Migration guides also disclose that extensions are fetched afresh and their private extension state may not transfer.
- Developer mode treats diagnostics as a user-enabled capability for a local server and packages useful evidence for handoff, with secret redaction. This is a useful UX direction even if the specific tooling is Chromium-native.
- The human takeover model is unusually clear: agent work is visible as a separate task, can be paused for a person, and asks before consequential actions. Consider only after provider, profile isolation, and consent boundaries are resolved.

## Safeguards, conflicts, and unknowns

- Preserve backlog policy: these are small, behavior-based issue slices. Do not combine layout, import, OCR, developer tooling, snippets, calls, and agents into a single YAB-inspired epic.
- The public product site calls the memory comparison a proof of speed but provides no benchmark method. Do not claim YAB’s WebKit footprint or performance translates to Chromium or use its numbers as thresholds. The Dia performance dossier remains the source for Dia vendor reports and Arcified’s measured-work recommendations.
- The YAB source surfaces disagree on current version, and some pages are marketing summaries while the manual/changelog contain different levels of detail. Record date/version with any later re-check. Changelog claims that typing lag, crashes, or tab loading were fixed still need runtime evidence before being treated as outcomes.
- Privacy statements are vendor policy claims, not a security audit. The site says there is no YAB account or first-party server reading browsing, but separately documents updates, daily activity (opt-out), crash reporting (opt-in), feedback, optional sync, and AI provider data flows. Verify each future Arcified data flow on its own terms.
- YAB’s direct import reads local browser files, requests macOS keychain access, and uses OS-specific Safari export. These are not proof of a safe Chromium importer on other systems. Unknown: current Arcified/native Chromium profile schemas, locked database behavior, permission UX, and field-by-field import fidelity remain to be audited before promising source-browser coverage.
- YAB’s manual describes Live Text, a floating call window, Developer Mode, and local-model commands, but this research did not run the app. Their actual behavior, accessibility, compatibility, and failure cases are unknown. The portable requirements above are recommendations, not observed Arcified support.
- YAB’s agent MCP and terminal tooling are product-specific. No install or `yab setup` command was run; no accounts were connected; no cookies, pages, or private user data were accessed.
